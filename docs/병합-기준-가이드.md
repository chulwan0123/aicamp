# 플러스홈 병합 기준 가이드

> **SILVER 통합 상태(2026-08-21)**: 운영 기준은 `https://aicamp-sigma.vercel.app`이다. 현재 클라이언트 연결은 `js/silver-engine.js`, 공유는 `/api/share`, 공시가격은 `/api/price`, 실거래는 `/api/market`, 단지 검색은 `/api/complexes`가 담당한다. 아래의 과거 정적 목업 설명보다 현재 코드와 `IMPLEMENTATION.md`가 우선한다.

> **이 문서의 용도**
> 이 저장소의 코드를 **기준(base)** 으로 삼아 다른 작업본을 병합할 때 쓰는 지침이다.
> 사람이 읽어도 되고, AI 세션에 그대로 프롬프트로 붙여 넣어도 된다.
>
> **범위**: 사용자 입력 수집 → LLM 보고서 생성 → 화면 렌더링.
> 세율 규칙셋(`rules.js`)과 보유세 계산(`holdingTax.js`)은 이 문서의 범위 밖이며,
> `docs/보유세-검증산식-인수인계.md` 를 따른다.

## 0. 병합 원칙 — 한 문장

**이 저장소의 아키텍처와 데이터 계약이 기준이다.** 다른 작업본의 변경은 이 계약을 지키는 형태로 옮겨 온다. 계약을 바꿔야 한다면 먼저 이 문서를 고치고, 그다음 코드를 고친다.

## 1. 아키텍처 — 규칙 엔진이 계산하고, AI가 판단한다

```
사용자 입력 8단계
      │
      ├── 사실 정보 ──→ scenarios.js ──→ computed
      │   (연령·명의·주소·취득·희망지역·소득)   금액 + 산식 + 법령 근거
      │                                            │
      └── 성향 5문항 ──────────────────────────────┤
                                                   ▼
                                                 LLM
                                    성향 점수 · 추천안 선정 · 문장 생성
                                                   │  draft
                                                   ▼
                                              verify(draft, computed)
                                                   │
                                                   ▼
                                    assemble({ computed, draft })
                                    금액은 computed, 문장은 draft
                                                   │  advice
                                                   ▼
                                            renderReport(advice, …)
```

### 왜 이 구조인가

초기 설계는 LLM이 세액을 직접 계산했다. 실측 결과 **양도소득세를 62% 과다 산출**했고(공동명의 지분 분할 누락), 총액을 월액 자리에 넣었으며, 규칙셋에 있던 참조값을 계산 없이 그대로 베꼈다.

그래서 **LLM에게서 산술을 회수했다.** `assemble()` 이 최종 응답을 조립할 때 모든 금액을 `computed` 에서 가져오므로, LLM이 숫자를 틀려도 화면에 반영될 수 없다.

### 이 원칙을 깨는 변경은 받지 않는다

- LLM 응답에서 금액을 읽어 화면에 표시하는 코드
- 프롬프트에 "계산하라"는 지시를 되살리는 변경
- `assemble()` 을 우회해 `draft` 를 그대로 응답으로 내보내는 변경

## 3. 데이터 계약

이 네 가지 형태를 바꾸는 변경은 병합 전에 합의가 필요하다.

### 3-1. `payload` — 클라이언트 → `/api/advise`

```js
{
  property: {            // js/property.js 의 lookupProperty() 결과
    address, officialPrice, marketPrice, confidence, tradeCount, areaM2,
    complexName, dong, ho, pyeong, region, isCapitalArea,
    acquisitionYear, acquisitionPrice,
  },
  subject: {             // js/silver-engine.js 의 collectSubject()
    age, spouseAge, ageBands: { father, mother },
    houseCount, ownership,              // 'JOINT_50_50' | 'SINGLE'
    holdingYears, acquisitionYear, acquisitionPrice,
    isResiding, residencyBand,
    wishRegion, wishRegionIsCapitalArea, // ★ 2027 특례 판정에 쓰인다
    monthlyIncome, targetExpense,
  },
  answers: {             // js/silver-engine.js 의 collectAnswers() — 선택지 원문 문자열
    inheritance, residency, urgency, liquidityForm, familyConsensus,
  },
  refinements: { … },    // 화면에서 되물어 받은 추가 입력 (선택)
}
```

**중요**: `answers`(성향)는 계산에 들어가지 않는다. `scenarios.js` 는 `{ property, subject }` 만 받는다. 성향은 LLM에게만 전달되어 추천안 선정에 쓰인다. 이 분리를 유지한다 — 성향이 금액을 움직이면 "왜 이 금액인가"를 설명할 수 없게 된다.

### 3-2. `computed` — `buildScenarios({ property, subject })` 결과

```js
{
  cashflow:   { monthlyIncome, targetExpense, monthlyShortage, annualHoldingTax,
                annualShortage, steps[], basis },
  display:    { … },      // LLM 이 문장에 인용할 서식화된 금액 (억·만원 한글)
  taxes:      { holding[3], holdingNote, holdingBasis, sale2026, sale2027Special },
  options:    { SELL, DOWNSIZE, PARTIAL, PENSION },   // 네 키 항상 존재
  giftReview: { considered, giftTax, acquisitionTax, cashNeeded, steps[], basis },
  meta:       { ownerCount, youngerAge, olderAge, drawdownYears,
                specialApplicable, assumptions[] },
}
```

각 `options[id]` 는 다음을 갖는다.

```js
{
  eligible: true | false,
  reason,                 // eligible: false 일 때 사유
  monthlyNet,             // 월 실수령 (eligible: true)
  monthlyFlow: [{ label, amount }],
  proceeds | breakdown: [{ label, amount, formula?, subtotal? }],
  allocation: [{ label, amount, note }],
  remainingAssets: { home, deposit, financial, total, note },
  steps: [],              // 산식 문자열
  basis: string | string[],  // 법령 근거
}
```

**금액 행의 규칙**
- `subtotal: true` 인 행은 그 앞 행들의 누계와 일치해야 한다
- 차감 항목은 음수로 넣는다
- `formula` 는 그 행의 산식을 짧게 적는다

**산식(`steps`) 문자열 형식**
`설명 = 식 = 결과` 로 쓴다. `render.js` 의 `parseStep()` 이 ` = ` 로 잘라 화면에 3분할해 그린다. 앞에 공백 두 칸을 두면 앞 단계에 딸린 보조 계산으로 들여쓰기된다.

```
집을 팔아 남은 이익 (양도차익) = 판 값 47억원 - 사신 값 10억 8,247만원 - 들어간 비용 5,000만원 = 35억 6,753만원
  방법 1로 내면 = 한 분 295만 1,100원 × 2명 + 농특세 20% = 708만 2,640원
```

### 3-3. `draft` — LLM 응답

```js
{
  profile: { inheritance, residency, urgency, note },   // 0~100
  cashflowSummary,
  recommendedId,          // eligible: true 인 것만 가능
  label, headline, why, tradeoff,
  cautions: [],
  actionPlan: [{ title, desc }],
  alternatives: [{ id, oneLiner }],
  excluded: [{ id, reason }],
  familyNote,
}
```

**LLM은 금액 필드를 반환하지 않는다.** 문장 안에서만 `computed.display` 의 값을 인용한다.

### 3-4. `advice` — `assemble()` 결과, 화면이 받는 최종 형태

```js
{
  profile, cashflow, recommended, alternatives, excluded,
  details: { taxes, options, giftReview },
  evidence: [{ title, steps[], basis, estimated?, upcoming? }],
  refine:   { title, intro, accuracy, fields, answers, applied, assumptions },
  familyNote,
  _source: 'llm' | 'rules',
}
```

## 4. 절대 지켜야 할 규칙

### 4-1. 폴백은 다른 주택이나 정적 금액을 사용하지 않는다

입력 오류는 명시적으로 알리고, AI만 실패한 경우에는 같은 입력과 계산값으로 규칙 기반 설명을 만든다.

| 실패 지점 | 폴백 |
|---|---|
| 데이터셋 로드 실패 | 조회 실패로 처리하고 오류 표시 |
| 미등록 주소 | 다른 단지로 바꾸지 않고 주소 재확인 요청 |
| LLM 호출 실패 / 검증 실패 | `api/_lib/fallback.js`가 현재 `computed`로 규칙 추천 생성 |
| 서버 자체 다운 / 55초 타임아웃 | 분석 실패로 처리하고 입력 화면에서 재시도 안내 |

### 4-2. API 키는 서버리스 함수 안에서만 쓴다

`api/advise.js` 밖에서 `OPENAI_API_KEY` 를 참조하면 안 된다. 클라이언트 번들에 절대 들어가지 않는다.

### 4-3. 모델 파라미터는 협상한다

`gpt-5` 계열은 `temperature` 와 `max_tokens` 를 거부한다. `callOpenAI()` 가 400 응답의 `"param"` 필드를 읽어 그 파라미터만 떼고 재시도한다(최대 3회). 이 로직을 지운 채 특정 모델에 하드코딩하면 안 된다.

`temperature: 0` 을 걸 수 없어 문장 표현은 호출마다 조금씩 달라진다. **수치의 일관성은 `rules` 주입과 `verify()`가 지킨다.** 완전한 재현이 필요하면 `USE_MOCK=true`로 규칙 기반 경로를 실행한다.

### 4-4. 금액은 억·만원 한글 단위로 쓴다

- 화면 표기: `js/format.js` 의 `fmtKRW()`. 1,000만원 이상은 만원 단위, 미만은 천원 단위로 반올림
- 산식 표기: `fmtKRW(n, { exact: true })`. 반올림 없이 정확한 값
- `verify()` 가 LLM 문장에서 7자리 이상 숫자를 찾으면 다시 쓰게 한다

### 4-5. 계산 결과가 숫자가 아니면 예외를 던진다

`calc.js`·`holdingTax.js`·`scenarios.js` 의 `round()` 는 `NaN` 을 만나면 `TypeError` 를 던진다. `Math.round(n || 0)` 으로 되돌리면 안 된다. 실제로 이 가드가 없어서 취득가액 누락이 양도세 0원으로 조용히 흘러간 적이 있다.

### 4-6. 2027년 특례 표기

2026년 세제개편안에 담긴 **2027년 시행 예정** 제도다. "없는 제도"나 "가정"으로 표현하지 않는다.

- 요건: 만 65세 이상 · 1세대1주택 · 수도권 주택 양도 · **6개월 이내 비수도권 이전**
- 감면: 양도소득세 50%, **최대 5억원**
- 추징: 양도 후 5년 이내 수도권 주택 취득 또는 수도권 복귀

`verify()` 가 이 특례를 활용한 추천에서 **법률 확정 필요**와 **5년 추징 조건**이 `cautions` 에 없으면 재작성을 요구한다.

## 5. 말투 규칙

70세 어르신이 혼자 읽고 이해해야 한다. 은행 안내문이 아니라, 잘 아는 사람이 옆에서 설명해 주는 말투다.

- **해요체를 쓴다.** `-습니다` 를 쓰지 않는다
- 한 문장 40자 안쪽. 한 문장에 한 가지만
- 어려운 말은 풀어 쓰고 원래 용어를 괄호에 넣는다
  - ○ `집을 팔아 남은 이익 (양도차익)` / `재산세 매기는 기준 금액`
  - ✗ `고가주택 과세비율` / `공정시장가액비율` / `소득인정액`
- 숫자를 먼저 말하고 뜻을 붙인다
- `반드시`·`보장`·`무조건` 같은 단정 표현을 쓰지 않는다
- 겁주지 않는다. 걱정되는 점은 알리되 무엇을 하면 되는지 함께 말한다

이 규칙은 기존 화면 문구(`index.html`), 결과 값 연결(`silver-engine.js`), 산식 라벨(`calc.js`·`holdingTax.js`·`scenarios.js`), LLM 프롬프트(`prompt.js`)에 적용돼 있다. 병합할 때 한 곳만 고치면 톤이 어긋난다.

## 7. 병합 절차

### 7-1. 시작 전

```bash
cd plushome
git init && git add -A && git commit -m "병합 전 기준점"
```

**저장소가 아직 git이 아니다.** 병합 중 파일이 유실돼도 되돌릴 수단이 없다. 반드시 먼저 한다.

### 7-2. 순서

1. **데이터 계약부터 맞춘다** — 3장의 네 형태가 양쪽에서 같은지 확인한다. 다르면 이 저장소 쪽으로 맞춘다
2. **`api/_lib/` 를 먼저 병합한다** — 계산이 맞아야 화면을 볼 수 있다
3. **`js/silver-engine.js` 어댑터를 맞춘다** — 계산 결과를 기존 DOM에 값으로 연결한다
4. **`index.html`은 최소 패치만** — CSS·에셋·DOM 기준선을 보존한다
5. **인라인 화면 셸은 마지막** — 화면 번호와 입력 수집이 앞의 변경과 맞물린다

### 7-3. 충돌 시 판단 기준

| 상황 | 선택 |
|---|---|
| 계산 로직이 다르다 | **검증값을 재현하는 쪽** (8장 기준값 대조) |
| 데이터 형태가 다르다 | 이 저장소 계약 |
| 화면 문구가 다르다 | 5장 말투 규칙에 맞는 쪽 |
| 한쪽에만 있는 기능 | 계약을 깨지 않으면 가져온다 |
| 판단이 안 선다 | 가져오지 말고 표시해 둔다. 나중에 붙이는 게 잘못 붙이는 것보다 싸다 |

### 7-4. 병합 후 확인

```bash
# 문법
for f in api/_lib/*.js api/*.js js/*.js scripts/*.js; do node --check "$f" || echo "FAIL $f"; done

# 계산 재현
npm run dev
curl -s -X POST http://localhost:3000/api/advise \
  -H 'Content-Type: application/json' \
  -d @docs/샘플-payload.json | node -e "…"

# CSS 유실
grep -c 'evidence-question\|calc-step\|basis-list' index.html
```

브라우저에서 `http://localhost:3000` 으로 주소 입력부터 공유까지 완주한다.

## 9. 알려진 미해결 항목

| 항목 | 상태 | 영향 |
|---|---|---|
| `scenarios.js` 가 `refinements` 를 `holdingTaxByYear` 에 전달하지 않음 | **미해결** | 추가 입력을 받아도 보유세에 반영되지 않는다. `buildScenarios({ property, subject })` 시그니처에 `refinements` 를 더해 넘겨야 한다 |
| 종합부동산세 재산세 중복공제 | 산식 확보, 코드 반영 확인 필요 | `docs/보유세-검증산식-인수인계.md` 2-4 |

| 공시가격 자동 조회 | 구현·배포됨 | 2025년 서울·경기 7,138,888세대 압축 조각 사용. PNU·동·호·전용면적 정확 일치, API 키 불필요 |
| 소방분 지역자원시설세 | 제외 | 고지서에 별도로 붙는다는 안내 필요 |
| `data/properties.json` | 검증 발췌 | 미등록 주소는 명시적으로 실패하며 반포자이나 다른 단지로 폴백하지 않음 |
